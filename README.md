# lbm-probe — 消费级 CPU 上的二维圆柱绕流数值实验

> **一句话**：用格子玻尔兹曼方法（LBM）在普通 CPU 上复现圆柱绕流，
> 并把结果与**权威基准**（Schäfer–Turek 1996）逐项对照。

## 结论（实测，四档配置）

| 量 | 最好档位 | 实测 | 文献 | 误差 |
|---|---|---|---|---|
| **Cd 均值** | τ=0.55 | 3.1831 | 3.1811 | **0.06%** |
| **Cd 最大** | τ=0.55 | 3.2326 | 3.2124 | **0.63%** |
| **St** | D=20 | 0.3031 | 0.30303 | **0.02%** |
| Cl 全幅 | τ=0.55 | 1.8838 | 2.003 | 5.95%（已知未解决，见下） |

五档配置（D=20 / D=30 / **D=40** / τ=0.55 / τ=0.57，Re=100，30 物理秒）**各自独立通过三道门禁**后才报数，
不是挑一个好看的。明细见 `benchmarks/grid/summary.md`。

## 这是什么

二维不可压流体绕过圆柱，雷诺数 Re=100，层流，尾流产生周期性涡脱落（卡门涡街）。
求解器用 **D2Q9 格子玻尔兹曼 + BGK 碰撞 + 半步反弹边界**，纯 Python + numpy，无 GPU 依赖。

对照基准：**Schäfer & Turek (1996)**，"Benchmark computations of laminar flow around a cylinder"，
NNFM 52, 547–566 —— 这是计算流体力学领域被广泛引用的标准算例。

## 怎么跑

```bash
python run_cylinder.py --run-seconds 10 --total-seconds 30   # 分段推进，可中断续跑
python run_cylinder.py --finalize                            # 只做门禁分析 + 出图
python run_cylinder.py --run-seconds 5 --legacy-outlet       # 归因对照：旧出口 BC
```

依赖：`numpy` + `matplotlib`（仅出图）。单档 30 物理秒在普通 CPU 上约 4–12 分钟。

## 🔴 这个项目真正的产出：三道门禁

上面的数字会过时，**下面这套方法不会**。

> **数值模拟里，「看起来收敛的数」和「真实收敛」是两回事。**
> **判据是守恒曲线，不是曲线形状好看。**

本项目跑过三轮，每一轮都被打回，每一条教训都是实测换来的：

### ① 质量守恒（拦住「发散片段伪装成正常数」）

第一轮：跑出「涡街可见、Cl 呈漂亮周期振荡、Cd 从 1.87 平滑降到 1.38」——**曲线形状很好看**。
复核方盯住全网格总质量一看：**前 100 步就跑到 10¹⁵ 量级** → 结果作废。

现在：求解器每 10 步记录流体总质量 `M = Σρ`，出 `mass_history.png`（**纵轴取对数**，指数发散一眼可见），
并内置**发散早停**（NaN/Inf 或质量超初值 10 倍 → 立即停机）。

**稳态窗口内漂移 < 0.1% 才准往下走。**

### ② 稳态判据（拦住「瞬态段当稳态」）

第三轮被打回：统计窗口取在了瞬态段（末尾 1 秒）——那一段质量平稳、Cd 却还在往下掉，
报出的 St/Cd 是「半路取的样」。

现在：把**最后 1/4 演化时长**自动切 4 个子窗，各算 Cd 均值，要求**相邻子窗相对变化 < 0.5%**。
窗口由代码自动裁，**不许手挑**。

⚠️ 判据**不看「Cd 是否恒定」**——圆柱绕流 Cd 自带约 2% 周期振荡，那是物理的一部分。

### ③ 才准报数

①②都过，才对稳态段做 St / Cd / Cl 与文献对照。任一不过 → 如实写「未收敛，X%/窗」。

## 还有三条同样值钱的教训

**④ 边界列上的宏量测量不可信。**
入口/出口的分布函数每步被边界条件覆写，在边界列上测到的通量是「**BC 施加的值**」，不是「真实流过的量」。
本项目因此一度误报「进出口流量差 5.388%」，与「质量守恒 0.0069%」自相矛盾。
沿 x 逐列扫描才发现：只有两端边界列异常，**内部各列彼此只差 0.02~0.42%**。
→ 测通量必须取**内部列**（离边界 ≥1 格）。这条对任何带入口/出口的 CFD 都成立。

**⑤ 「修好了」和「知道是哪一处修好的」是两件事。**
根因判定为「碰撞没跳过固体」，修了，但同时做了**单变量隔离实验**：保留修复、只把出口换回旧整列拷贝 BC
（`--legacy-outlet`）→ 该档**两道门禁全红**：守恒漂移 0.88%（判据 <0.1%），Cd 四子窗从 1.05 一路掉到 0.92，根本没到稳态。
换回对流出口 → Cd 回 3.1 以上。⇒ 真正让物理错的是**出口边界条件**，固体碰撞 bug 虽真，却被反弹边界隔离在固体内部。

**⑥ 频率估算的分辨率陷阱。**
St 恒定偏低 7.6%，四组实验纹丝不动。最后查出来：**FFT 频率分辨率 = 1/窗口长**，
7.5 秒的窗口量化误差就接近 5%。换**过零法**（数 Cl 过零次数）后误差从 7.66% 降到 0.02%。
另加一个修正：bounce-back 壁在固体掩码外半格，**有效直径是 D+1 不是 D**（再贡献 2.5%）。

## ⚠️ 已知未解决

**Cl 全幅偏低 6~14%（最好档 5.95%）**；五档按 τ 重排后，Cl 误差**总体上升但有一处回落**（见下）。

**结构性事实（10-28 D40 关单后确认）**：五档 **Re 全为 100**，而 LBM 中 τ = 3ν + 0.5、ν = U·D/Re
→ **固定 Re 时 τ、D、U 三者只能动两个**：D 组（U 固定，τ ∝ D，0.56 → 0.59 → 0.62）与 τ 组（D 固定，τ ∝ U）
是**两类实验**，拼在一起画不出 τ 的单变量曲线，**分辨率与黏性离散的贡献现有数据分不开**。

诊断已做（排除法）：
- ❌ 不是口径问题：谐波能量占比 **0.00%**（纯正弦）、max-min 与 RMS×2√2 两种方法一致、换窗口不敏感
- ❌ 不是归一化问题：Cd 与 Cl 共用同一归一化，Cd 误差仅 0.06%
- 🟡 **不是「网格不是主因」——是「分不开」**：D20→D40 三项指标随 D（同步随 τ）单调变差
  （St 0.02% → 0.97% → 1.58%，Cd_max 1.53% → 4.53% → 5.43%，Cl 全幅 8.97% → 13.81% → 14.23%）
  ——网格加密想减小空间离散误差，但同时抬高黏性离散误差，两者竞争，净效果可以是「加密反而更差」。
  **这是 LBM 固定 Re/Ma 下的固有性质**，不是实现 bug。
- 🟡 曾假设：动量交换法 + bounce-back 对**切向力**的系统性低估（压差主导的 Cd 不受影响，切向主导的 Cl 受影响）

**2026-10-27 已做控制体对照（`benchmarks/force_compare/`），该假设未获支持。** 同一条 D20 稳态轨迹并行 10 秒（≈3 个涡脱落周期）：
- 两法 Cd 均值差 **16.26%**（3.1481 vs 2.6362）、Cl 全幅差 **22.91%**（1.8232 vs 1.4055），**控制体反而更低**，方向与假设相反；
- 但控制体自身的 Cd 均值比文献低 **17.13%**（动量交换只低 1.04%）——Cd 由压差主导，若两法只差切向力，Cd 不该差 0.51；
- 所以这次对比**既不能支持、也不能证伪**原假设：控制体实现没做过解析标定，不能当裁判。
- ✅ **独立复核（10-27，WorkBuddy 另起输出目录重跑 6 分 43 秒）**：Cd 均值 3.1481 / 2.6362、Cl 全幅 1.8232 / 1.4055、差值 22.91% —— **与原报告逐位一致**。数字不是写出来的，是复算出来的。

**当前判断（10-28，二次降级）**：五档按 τ 重排的 Cl 误差：**5.95 → 8.97 → 8.75 → 13.81 → 14.23%**
（τ=0.57 处回落，位于 **D 组与 τ 组的拼接缝上**——该处 U 从 0.1 跳到 0.1167，是两类实验的接缝，**不是物理非单调**）。
这 5 档固定 Re=100，τ 与 D、U 三者只能动两个 → **无法分离分辨率与黏性的贡献**（相关性证据见 `benchmarks/tau_axis/tau_axis.md`，其双变量警告同样适用于本段）。
在不知道主因的情况下加网格 = 花钱买更差的数，GPU 大网格计划暂停。
**下一步（唯一能把两者分开的单变量实验，10-28 已跑完）**：固定 D 与 U、只改 Re（Re→ν→τ）——
D=20 与 D=40 各补 Re=80/120 两档，四档全过三道门禁，数据见 `benchmarks/re_separation/re_separation.md`。

**自检（为什么不能用 Re=100 基准算其他档）**：D20 档 Cl 全幅随 Re 从 1.2509（Re=80）→ 1.8232（Re=100）→ 2.4625（Re=120），
变化 **−31.4% / +35.1%**——远超预估的 5%。拿 Re=100 基准去算会得到 Re=80"最差"（37.55%）、Re=120 次差（22.94%），
**趋势完全颠倒**。Cl 随 Re 快速上升是**真实物理**（圆柱绕流 Re≈190 进入临界区，振幅加速增长），不是数值错误。

**Re 实验结果（差值口径）**：同 Re 下 D40/D20 的 Cl 比值——0.9589（Re=80）→ 0.9423（Re=100）→ 0.9261（Re=120），
即**加密到 D=40 的净代价从 4.11% 单调升到 7.39%**。

🔴 **诚实边界（本轮判不了主因）**：固定 Re 下改 D，τ 必然跟着变（τ ∝ D）→ **两个网格的黏性也不同**。
差值 = 「黏性变差的量」与「空间变好的量」之**差**，不是单边的分辨率效应——原耦合问题没有消失，只是换了个形式。
**主因（黏性 vs 空间）本轮无法单独判定**；要判需要独立标定的 Cl(Re) 曲线（文献只有 Re=100）或高分辨率参考解。

**本轮能下的结论（够扎实）**：
1. **量化了加密网格的净代价**：同 Re 下 D20→D40，Cl 系统性偏低 4~7%；
2. **占比随 Re 单调上升**（比值 0.959 → 0.942 → 0.926）⇒ 网格与黏性的**相对权重随 Re 变**，不是固定负收益 ⇒ **GPU 大网格计划维持暂停**；
3. 「加密不划算」这一判断在三个 Re 上都成立——在搞清楚主因之前，加网格仍然是花钱买更差的数。

面试被问到就这么答——知道边界在哪，比四个数全对准更可信。
